01 · Punto de partida

¿Qué cambia cuando un LLM deja de limitarse a generar texto?

Un modelo puede explicar, resumir o razonar. Pero cuando necesita consultar datos actuales, leer una base de datos o ejecutar una acción, necesita algo más: una herramienta externa.

Tool Use conecta la capacidad de razonamiento del modelo con software que realmente puede hacer cosas.
02 · El problema

El LLM no tiene acceso automático al mundo exterior.

Datos actuales

Información cambiante

Tiempo, cotizaciones, disponibilidad, pedidos o incidencias pueden cambiar después del entrenamiento.

Sistemas privados

Datos internos

Una base de datos, CRM o agenda no son visibles para el modelo salvo que una aplicación le dé acceso.

Acciones

Efectos reales

Enviar, guardar, crear, actualizar o ejecutar requiere código y permisos fuera del modelo.

03 · Definición

Tool Use = el modelo solicita una capacidad externa.

La aplicación ofrece un conjunto de herramientas bien descritas. El modelo decide cuándo necesita una de ellas y con qué argumentos. El software valida y ejecuta la petición.

El modelo decide qué necesita. El software decide qué puede ejecutar.

05 · Una tool real

Una herramienta puede ser una función normal de Python.

def consultar_agenda(fecha): eventos = { "2026-10-25": ["09:30 Mentoría", "18:00 Bootcamp"] } return eventos.get(fecha, [])

La función no sabe nada de LLMs. Solo recibe una entrada y devuelve un resultado. La parte de IA aparece cuando describimos esa función al modelo y permitimos que la solicite.

06 · Function Calling

El modelo necesita saber qué herramienta existe y cómo pedirla.

Nombre

consultar_agenda

Descripción

Consulta los eventos de una fecha concreta.

Argumentos

fecha: string

{ "name": "consultar_agenda", "arguments": { "fecha": "2026-10-25" } }
07 · Demo simulada

Dos necesidades, dos herramientas.

La pregunta combina información de agenda y tiempo. Observa cómo el modelo no “sabe” la respuesta: va obteniendo piezas mediante herramientas.

Tool Use tracePaso 0/7
USER › ¿Qué reuniones tengo mañana y qué tiempo hará?
LLM › Necesito consultar agenda y meteorología.
TOOL CALL › get_calendar_events(date="2026-10-25")
TOOL RESULT › 09:30 Mentoría · 18:00 Bootcamp
TOOL CALL › get_weather(city="Madrid", date="2026-10-25")
TOOL RESULT › 18 °C · lluvia débil
LLM › Mañana tienes dos reuniones y se espera lluvia débil, con una máxima de 18 °C.
Qué observar

El modelo no ejecuta directamente

Genera una solicitud estructurada. La aplicación recibe la petición, valida los argumentos, ejecuta la función y devuelve el resultado.


Resultado: el LLM puede combinar información procedente de varias tools antes de responder.

08 · Ecosistema

¿Qué puede ser una herramienta?

Función Python

Cálculos, validaciones, lógica interna.

API REST

Tiempo, mapas, pagos, modelos externos.

Base de datos

Consultar o modificar información estructurada.

Archivos

Leer, generar o transformar documentos.

Servicios SaaS

Correo, calendario, CRM, tickets.

Procesos internos

Automatizaciones y lógica de negocio.

10 · Agentes

Tool Use es una capacidad. Un agente es un sistema.

Un agente puede decidir qué hacer, elegir herramientas, observar resultados y continuar. Tool Use le da la capacidad de interactuar con el entorno.

11 · Seguridad

Dar herramientas a un modelo implica poner límites.

Allowlist

El modelo solo puede pedir herramientas previamente autorizadas.

Validación

Comprobar tipos, rangos y contenido antes de ejecutar.

Permisos mínimos

Cada herramienta debe tener solo el acceso estrictamente necesario.

Confirmación humana

Acciones sensibles pueden requerir aprobación explícita.

Secretos protegidos

Las API keys no se exponen al modelo ni al usuario.

Logs y observabilidad

Registrar qué tool se llamó, con qué argumentos y qué ocurrió.

12 · Caso completo

Del lenguaje natural a una acción controlada.

Usuario: "Busca el pedido 4182 y dime si ya salió."
1. LLM identifica intención
2. Solicita buscar_pedido(id=4182)
3. Orquestador valida el ID
4. La herramienta consulta la BBDD
5. Resultado: {"estado": "enviado", "fecha": "2026-10-24"}
6. El resultado vuelve al LLM
7. LLM responde en lenguaje natural
La IA aporta comprensión y lenguaje. El software aporta acceso, reglas y ejecución.
13 · Cierre

Tres ideas para llevarte

1

El LLM no hace magia

Solicita una herramienta mediante una interfaz estructurada.

2

El software mantiene el control

Valida, autoriza, ejecuta y devuelve el resultado.

3

Tool Use habilita sistemas más capaces

Es una pieza fundamental en agentes y automatizaciones con IA.

El modelo decide qué herramienta necesita. El software la ejecuta de forma controlada.
